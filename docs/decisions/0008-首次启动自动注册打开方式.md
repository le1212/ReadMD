# 决策：首次启动自动加入“打开方式”候选，并保留可见入口

- 日期：2026-11-16
- 状态：已采纳

## 背景

0006 已经实现“按用户注册候选身份 + 系统窗口确认默认”，但入口只有两个：

1. 欢迎页底部的链接；
2. 原生菜单“文件 → 设为默认 Markdown 打开方式…”。

实际使用中这两个入口都不可见：

- ReadMD 启动会恢复上次打开的文档，有文档时欢迎页不显示，链接随之消失；
- 窗口设置了 `autoHideMenuBar: true`，菜单栏默认收起，只有按 `Alt` 才出现。

结果：用户右键 `.md` → “打开方式”看不到 ReadMD，应用内也找不到设置入口。功能存在，但对普通用户等于不存在。

## 对标与调研

| 产品 | 做法 | 启示 |
| --- | --- | --- |
| Visual Studio Code | 安装器把编辑器注册为文件类型候选，并写入“用 Code 打开”右键菜单；默认程序仍由用户在系统里确认 | 候选身份应在“安装/首次运行”时自动建立，不应要求用户先找到设置 |
| Typora | 安装器提供文件关联选项；运行时也有设置入口 | 自动注册 + 手动入口可以并存 |
| Obsidian | 安装器声明支持的文件类型；便携/非安装场景下由应用自身维护 | 便携应用必须在运行时自行注册 |
| 0006 调研 | electron-builder 的 `fileAssociations` 只对 NSIS 安装器生效，便携版必须运行时注册 | 自动注册放在主进程启动阶段，而不是打包配置 |

## 决策

1. 打包版每次启动时检查关联状态：
   - 未注册 → 自动写入候选身份（ProgID、`OpenWithProgids`、`Capabilities`）；
   - 已注册但 exe 路径变化 → 自动更新命令；
   - 只写 HKCU，不修改 `UserChoice`，不改变默认程序。
2. 新增持久化字段 `associationOptOut`：
   - 用户在应用内点“从打开方式列表移除 ReadMD”时设为 `true`，之后启动不再自动注册；
   - 用户再次主动点“去设置”时清除该字段。
3. 在命令栏增加一个齿轮图标（无文字标签，`title`/`aria-label` 说明），点击直接打开“打开方式”面板；欢迎页链接和 `Alt` 菜单保留。
4. 冒烟测试环境不写注册表；自动注册逻辑只对打包版生效。

## 影响与风险

- 首次启动会多写几个 HKCU 键值，可随时在应用内移除；不产生费用，不需要管理员权限。
- 不会自动成为默认程序：Windows 仍要求用户在系统窗口里亲自确认。
- 用户明确移除后不会被“自动注册”反复骚扰。
- 仍然只注册 `.md` / `.markdown` / `.mdown` / `.mkd`；新增的只读预览格式不自动注册，避免改动用户已有的 PDF/Word 打开方式。
