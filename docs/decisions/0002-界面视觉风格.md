# 决策：卡片式界面视觉风格

- 日期：2026-10-20
- 状态：已采纳

## 背景

初版界面能完成功能，但视觉上更像“把控件拼在一起”：按钮高度不一致、图标大小混杂、卡片之间缺少统一的间距节奏，文件树、工具栏和状态栏的边界也不够清晰。

用户提供了一张后台管理界面的截图作为风格参考，并明确要求：**组件和样式对齐、大小统一、整体更精致**。

## 参考与原则

参考图的核心不是具体业务，而是这套视觉语言：

| 元素 | 参考做法 | ReadMD 的落地 |
| --- | --- | --- |
| 画布 | 浅灰背景，内容以白色卡片浮在上面 | 浅灰渐变画布 + 白色悬浮面板 |
| 容器 | 大圆角、细边框、柔和阴影 | 侧边栏/命令栏/文档卡片统一 16–18px 圆角 |
| 控件 | 高度一致，图标风格统一 | 所有常规按钮/图标按钮 34px；工具栏图标 16px，顶栏图标 18px |
| 间距 | 稳定的 8px 节奏 | 4 / 8 / 12 / 14 / 20 / 24px 设计变量 |
| 选中态 | 浅色底 + 主色文字 | 文件树/标签/大纲使用浅蓝底 + 蓝色文字 |
| 层级 | 侧边栏、顶部操作区、主内容卡片 | 侧边栏卡片 → 命令栏卡片 → 文档卡片（含状态栏） |
| 深色模式 | 深灰底、低对比边框 | 独立深色变量，保持同样的间距和圆角 |

**不引入 Tailwind、Ant Design 等 UI 框架**：本项目界面规模小，引入组件库会带来额外体积、构建复杂度和风格锁定；用 CSS 变量 + 原生 CSS 更容易保持统一，也方便后续替换。

## 决策

- 重写 `renderer/index.html` 的结构：品牌区放入侧边栏卡片；主区域拆成“命令栏”和“文档卡片”。
- 重写 `renderer/styles.css`：以 CSS 变量统一颜色、圆角、阴影、控件高度、间距；删除旧版顶部栏和浏览器式标签样式。
- 标签页改为胶囊式标签，放在文档卡片顶部；状态栏收进文档卡片底部。
- 空状态只保留一处入口，避免侧边栏同时出现“未打开文件夹”和“还没有打开文件夹”的重复信息。
- 保留所有现有 DOM id 和交互逻辑，避免 UI 重构影响文件读写、保存、查找、导出等功能。

## 影响与风险

- **功能零改动**：只调整 HTML 结构与 CSS；`npm run smoke` 的文件树、标签页、查找、HTML/PDF 导出、保存测试全部通过。
- **维护成本低**：颜色、圆角、控件高度、侧边栏宽度都集中在 `:root` 变量中，后续调整只需改一处。
- **可逆**：旧版样式已被完全替换；若需要回退，可从版本记录恢复 `index.html` / `styles.css`。
- **风险**：自定义 CSS 需要持续保持规范；新增组件应复用 `.btn`、`.icon-btn`、`.panel` 等类，不要临时写高度和间距。
