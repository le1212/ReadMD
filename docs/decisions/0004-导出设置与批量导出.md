# 决策：导出设置、封面目录与批量导出

- 日期：2026-10-21
- 状态：已采纳（v0.3.0 实施）

## 背景

0.2.0 已经能导出 Word / PDF / HTML，排版规范也统一了，但所有导出的版式是固定的：

- 想要“报告/论文”风格的用户，需要正文首行缩进 2 字符；
- 想要“正式材料”的用户，需要封面、页眉和目录；
- 一个文件夹里有几十篇 Markdown 时，只能一篇一篇导出；
- 每次导出都要重新选择同样的选项，无法记住偏好。

用户明确要求继续实现：导出设置面板（首行缩进、页眉页脚开关、封面、目录），以及批量导出整个文件夹。

约束：

- 不引入新的重型运行时（继续避免 Pandoc / LaTeX / Puppeteer）；
- 不改变“Markdown 是唯一源文件”的原则，导出只是生成副本；
- 批量导出不能静默覆盖用户已有文件；
- 设置要简单到非技术用户能看懂，不能出现“CSS 分页”“域代码”这类术语；
- Word、PDF、HTML 三个格式尽量共享同一套设置和观感。

## 对标与调研

| 产品/方案 | 相关做法 | 对本项目的启示 |
| --- | --- | --- |
| Typora | PDF 导出提供纸张、页边距、主题、页眉页脚、分页选项；Word 通过 `reference.docx` 控制样式 | 设置项按“用户能理解的版式概念”组织：排版风格、页眉、页脚、封面、目录 |
| Pandoc | 支持 metadata、目录、模板、参考文档；PDF 目录页码由 LaTeX/排版引擎计算 | Word 用原生目录域；PDF 若没有排版引擎，目录页码不能凭空得到 |
| Microsoft Word | 原生目录（TOC 域）、封面页、首页不同、页码域 | Word 侧全部使用原生能力，用户打开后仍可更新目录和页码 |
| Obsidian | PDF 导出依赖 Chromium 打印，设置相对有限 | Chromium 打印适合正文，但目录页码需要额外排版引擎 |
| [Paged.js](https://pagedjs.org/)（MIT） | 浏览器端 paged media polyfill，可用 `target-counter` 生成目录页码、页眉页脚 | 能力最完整，但会改变现有 PDF 分页链路，回归风险高；本期不引入 |
| `pdf-parse` / `pdfjs-dist` | 可解析生成的 PDF，二次提取标题页码 | 体积约 32–34MB，且需要“生成两次 PDF”；为一个目录页码引入不划算 |

结论：

- Word 目录用 `docx` 的 `TableOfContents`，页码和书签由 Word 自己维护；
- PDF/HTML 目录用标题锚点生成可点击清单，不显示页码；
- 批量导出用 Vditor 自带的 `Vditor.md2html` 渲染，避免再引入 Markdown 解析器；
- 不为了 PDF 目录页码引入 Paged.js 或 PDF 解析库，保持现有 PDF 链路稳定。

## 决策

### 1. 导出设置

保存到应用状态的 `exportSettings`，默认值：

```json
{
  "formal": false,
  "header": false,
  "footer": true,
  "cover": false,
  "toc": false,
  "coverSubtitle": "",
  "coverAuthor": ""
}
```

| 设置 | 行为 |
| --- | --- |
| 排版风格：通用 | 不缩进，段后 6pt，用段间距区分段落 |
| 排版风格：正式 | 正文首行缩进 2 字符；列表、引用、表格单元格不缩进 |
| 页眉 | 显示文档标题；Word 使用“首页不同”，启用封面时封面不显示页眉 |
| 页脚 | 显示“第 X 页 / 共 Y 页” |
| 封面 | 生成独立封面页；标题取文档第一个一级标题，找不到回退文件名；可填副标题和署名，日期自动 |
| 目录 | Word 生成原生 TOC 域；PDF/HTML 生成可点击的标题目录（至少 2 个标题才生成） |

- 设置面板用“开关 + 分段按钮”表达，不暴露 CSS/域代码；
- 设置保存在主进程状态文件，下次启动继续生效；
- 所有格式共用同一份设置，避免“Word 缩进、PDF 不缩进”的割裂。

### 2. 封面

- 标题来源：文档第一个 `<h1>`；没有一级标题时使用文件名；
- 副标题、署名可选；日期使用导出当天；
- Word：
  - 封面由标题、分隔线、副标题、署名/日期组成，末尾插入分页符；
  - 设置 `titlePage: true`，封面页使用空的页眉/页脚；
  - 封面页计入页码，正文从第 2 页开始；这是 Word 的常规行为。
- PDF/HTML：
  - 封面是整页布局（`min-height: 238mm`），标题区在页面上半部，署名/日期在底部；
  - 短装饰线放在标题上方，避免“装饰线在页顶、标题在页中”的割裂感；
  - PDF 封面页也会显示用户开启的页眉/页脚；设置面板里有提示。

### 3. 目录

- Word：
  - 使用 `TableOfContents('目录', { hyperlink: true, headingStyleRange: '1-4' })`；
  - 目录标题是普通段落，不进入目录本身；
  - 目录后插入分页符；
  - `features.updateFields: true`，Word 打开时更新页码；
  - `docx` 会为标题生成 `_TocN` 书签和 `PAGEREF` 域，目录条目可点击。
- PDF/HTML：
  - 从 HTML 的 `h1`–`h4` 提取标题，缺失 id 时补 `readmd-heading-N`；
  - 生成带层级缩进的 `<nav class="readmd-toc">`，链接到标题锚点；
  - Chromium 会把 `#anchor` 保留为 PDF 内部 Link 注释，因此 PDF 目录可点击；
  - **不显示页码**：Chromium 不提供 `target-counter` 能力。这是本期明确的取舍，已写入已知限制和后续路线图。
- 少于 2 个标题时不生成目录，避免只有一行、单独占一页的尴尬。

### 4. 批量导出

- 入口：导出菜单“批量导出当前文件夹…” → 选择 Word/PDF/HTML → 选择输出文件夹；
- 文件发现：
  - 递归扫描当前打开文件夹；
  - 跳过 `node_modules`、`.git`、`.svn` 和符号链接；
  - 只处理 `.md` / `.markdown` / `.mdown` / `.mkd` / `.txt` / `.text`；
  - 单文件超过 32MB 跳过；单次最多 300 个文件、目录深度最多 20 层；
- 渲染：
  - 主进程读取 Markdown 文本；
  - 渲染进程调用 `Vditor.md2html(markdown, { cdn })`，与编辑器使用同一套 Markdown 解析；
  - 然后再走单篇导出的同一条流程：公式补 MathML、图片路径解析、封面/目录生成；
- 输出：
  - 保留源文件夹的相对子目录结构；
  - 扩展名替换为 `.docx` / `.pdf` / `.html`；
  - 已存在同名文件时自动加 `(1)`、`(2)`，不覆盖；
  - 输出文件夹必须由用户通过系统对话框选择，主进程记录授权目录；渲染进程不能写入任意路径；
- 进度与失败：
  - 状态栏显示“批量导出 3/12：文件.md”；
  - 单个文件失败不中断整体，最后汇总成功/失败数量和前 3 条失败示例；
  - 完成后可一键打开输出文件夹。

### 5. 交互

- 顶部“导出”下拉菜单：
  - 导出 Word 文档
  - 导出 PDF 文档
  - 导出网页
  - 导出设置…
  - 批量导出当前文件夹…
- 文件菜单同步增加“导出设置…”和“批量导出当前文件夹…”；
- 设置面板宽 580px，使用与主界面一致的卡片、圆角、开关样式；
- 所有设置修改立即保存，不需要“应用”按钮。

## 影响与风险

- **PDF 目录没有页码**：这是最大的功能缺口；PDF 目录可点击跳转，Word 目录有页码。后续如果必须补齐，可评估 Paged.js 或两次生成 + PDF 文本解析，但会增加依赖和导出时间。
- **PDF 封面页眉/页脚**：Chromium 无法只对第一页隐藏页眉页脚；启用封面且同时开启页眉时，封面页仍会显示页眉。Word 通过“首页不同”避免了这个问题。
- **封面标题**：取第一个 H1；如果文档没有 H1，封面会使用文件名。标题过长时封面会换行，超过约 120 字会截断。
- **批量导出性能**：顺序处理，PDF 每篇都要启动一次隐藏打印窗口，文件多时耗时明显；单次 300 个文件是保护上限。
- **批量导出覆盖策略**：不覆盖，自动加序号；如果用户希望覆盖，需要后续增加“覆盖同名文件”选项。
- **设置作用域**：设置是全局的，不按文档保存；这符合普通用户“一次设置、长期使用”的预期。
- **可逆性**：导出只产生新文件，不改源 Markdown；设置保存在状态文件，可随时改回默认。

  - 完整设置 PDF：3 页（封面 + 目录 + 正文），文件头 `%PDF-`；
  - 批量导出：文件列表、`Vditor.md2html` 渲染、相对子目录写入、Word 文件头校验；
  - 导出设置面板：能打开，控件和封面字段完整；
  - 大纲悬浮提示在多次切换标签后仍能恢复。
- 目视检查：
  - 设置面板截图；
  - PDF 封面、目录、正文页渲染截图；
  - DOCX 预览截图（封面、目录、正文、表格、图片）。

## 备选方案

1. **Paged.js 生成 PDF**：可以同时解决目录页码、封面页眉隐藏、奇偶页页眉等问题；代价是替换现有打印链路，需要完整回归表格、代码块、图片和分页。
2. **两次生成 + PDF 解析**：先生成无页码目录的 PDF，解析标题页码，再生成一次；需要引入约 32–34MB 的 PDF 解析库，导出时间翻倍。
3. **只做 Word 目录**：PDF/HTML 不生成目录，减少复杂度；但用户在 PDF 中会失去快速导航，和“目录”设置的预期不符。
4. **批量导出改为后台队列**：支持取消、断点续传和并发；当前顺序处理更简单、可预测，先满足普通文件夹规模。
