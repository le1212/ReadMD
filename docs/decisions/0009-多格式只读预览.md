# 决策：HTML / JSON / PDF / DOCX 只读预览

- 日期：2026-11-16
- 状态：已采纳

## 背景

ReadMD 目前只把 Markdown/文本当作可打开文件。用户希望在同一窗口里查看常见的本地文档：

- HTML：需要预览；
- JSON：需要可读的格式化视图；
- PDF：需要翻页阅读；
- Word：需要查看 `.docx` 内容。

约束：

- 这是本地阅读器，网络与脚本默认不可信；
- 不能引入需要构建链（webpack/vite）的前端依赖，渲染进程直接加载本地脚本；
- 便携版离线可用；新增依赖必须允许商用、允许闭源分发；
- Markdown 的编辑体验不能回退；
- 首版控制范围，避免把 ReadMD 变成通用 Office 套件。

## 对标与调研

| 产品 | 相关做法 | 对本项目的启示 |
| --- | --- | --- |
| Visual Studio Code | HTML 用“集成浏览器”预览（等同于浏览器，脚本可运行）；JSON 有语言服务/折叠；PDF、Word 需装扩展 | 预览与安全要分级：ReadMD 不是浏览器，默认不执行脚本 |
| Obsidian | 原生显示图片、音视频、PDF；HTML/DOCX 不在原生支持范围 | PDF 内嵌阅读是阅读器的合理基线；Office 格式按需扩展 |
| Typora | 专注 Markdown，通过导出支持 PDF/Word，不把 Office 当阅读对象 | 不要把“兼容”理解成“编辑所有格式” |
| [mammoth.js](https://github.com/mwilliamson/mammoth.js) | DOCX → 语义化 HTML；BSD-2-Clause；npm 1.13.0，仍在维护 | 适合“阅读”而非“还原版式”，体积小、无构建依赖 |
| [pdf.js](https://github.com/mozilla/pdf.js) | Firefox 的 PDF 引擎；Apache-2.0；npm 6.5.438 | 跨平台、可控、无原生插件；需把 build/cmaps/standard_fonts/wasm 复制到本地 vendor |
| [docx-preview](https://github.com/VolodymyrBaydalka/docx-preview) | 浏览器端按页还原 DOCX；MIT | 版式更接近 Word，但依赖 DOM/JSZip 且输出更重；首版先选更轻的 mammoth |
| Electron `webview` | 可承载内置 PDF 查看器；官方文档建议尽量不用，且需 `webviewTag` | 不在首版引入 webview；PDF 用 pdf.js 渲染到 canvas，权限模型更简单 |

说明：VS Code 文档已核对 HTML 预览行为；Obsidian/Typora 文档页在本次网络环境下未能完整抓取，表中结论以其公开功能范围为参照。库的版本与许可证通过 npm registry 元数据核对。

## 决策

1. 新增只读文档类型：
   - `.html` / `.htm`：预览 + 源码切换；
   - `.json`：格式化只读视图（非法 JSON 显示原文与错误）；
   - `.pdf`：pdf.js 逐页渲染，按容器宽度缩放；
   - `.docx`：mammoth 转语义化 HTML 后只读预览。
2. 文件树、打开对话框、会话恢复、系统传参都识别这些类型；`batch` 导出仍只处理 Markdown。
3. 非 Markdown 标签页：
   - 隐藏 Vditor 工具栏、保存/导出/AI 等仅对 Markdown 有意义的按钮；
   - 不参与脏标记、不触发自动保存、关闭时不再询问保存；
   - 状态栏只保留“只读”这一必要状态。
4. HTML 预览安全模型：
   - 在 Shadow DOM 内渲染，样式与主界面隔离；
   - 移除 `script`、`iframe`、`object`、`embed`、`form`、`meta` 等主动内容与事件属性；
   - 主界面 CSP 已禁止内联脚本，且不执行 `javascript:` URL；
   - 外链点击交给系统浏览器（仅 http/https/mailto），不导航应用窗口。
5. PDF 由 pdf.js 渲染，关闭 PDF 内嵌脚本与 XFA；单文件上限沿用 32 MB；页数超过 200 页时只渲染前 200 页并提示。
6. DOCX 只支持 `.docx`；旧版二进制 `.doc` 明确提示“请另存为 .docx”，不做伪支持。
7. 新增依赖：`mammoth@1.13.0`（BSD-2-Clause）、`pdfjs-dist@6.5.438`（Apache-2.0）。pdf.js 的运行时文件通过 `scripts/prepare-pdfjs.js` 复制到 `renderer/vendor/pdfjs`，保证离线与打包一致。接入时执行 `npm audit --omit=dev`，生产依赖 0 漏洞；0.4.0 时期对 mammoth 旧版 `argparse` 的告警在 1.13.0 中已不存在。
8. 不把 `.html` / `.json` / `.pdf` / `.docx` 自动注册为 ReadMD 的打开方式；需要时由用户在应用内手动设置，避免改写用户已有的 PDF/Word 默认程序。

## 影响与风险

- 安装包体积增加约 18 MB（pdf.js 的 build/cmaps/fonts/wasm），可接受。
- mammoth 输出的是语义化 HTML，复杂版式（分栏、精确定位、页眉页脚、域、OMML 公式）不会与 Word 完全一致；这是“阅读优先”的取舍。
- HTML 预览不执行脚本，依赖脚本渲染的页面会显示为静态内容；这是明确的安全边界。
- PDF 的大文件/扫描件渲染会占用内存；已限制单文件大小与页数，并在渲染时按标签页取消。PDF 用 canvas 渲染，浏览器 `Ctrl+F` 无法搜索 PDF 文字。
- 新增格式均为只读；后续若要做 JSON/HTML 编辑，需要单独评估代码编辑器与保存模型，不在本次范围。
- 生产依赖审计为 0 漏洞；开发工具链（Electron / electron-builder）仍有上游公告，属于既有环境问题，升级 Electron 需单独做兼容验证。
